# Slither AI

Slither AI — исследовательский проект обучаемого игрового агента для Slither.io-подобной игры. **Конечная цель — обучить агента в собственной воспроизводимой среде, а затем исследовать его применение в официальной Slither.io через браузерное расширение:** расширение получает визуальную информацию, передаёт её модели и, если правила игры и доступные интерфейсы это разрешают, передаёт выбранные игровые действия. Пользователь запускает игру и сам включает/останавливает агента.

Это целевой результат, а не уже реализованная или гарантированная возможность. До разработки управления официальным клиентом необходимо отдельно проверить актуальные правила игры и допустимые способы интеграции. Не обходить антибот-защиту, не использовать приватный игровой протокол, скрытую инъекцию или механизмы уклонения от обнаружения. Если автоматическое управление не разрешено, поддерживаемый режим — визуальный анализ и рекомендации человеку.

## Статус

Начальная основа проекта и MVP локальной среды реализованы в коде, но runtime-валидация в целевом Linux-окружении ещё не подтверждена. PPO CLI добавлен, однако реальное обучение и оценка пока не запускались. Браузерное расширение, vision pipeline и онлайн-интеграция ещё не реализованы.

## Планируемая архитектура

- `slither_ai/envs` — локальная игровая среда и правила.
- `slither_ai/agents` — политики и обёртки агентов.
- `slither_ai/training` — обучение, оценка и сохранение checkpoints.
- `slither_ai/vision` — распознавание игрового поля по изображению.
- `slither_ai/integration` — интерфейс между моделью и внешней игрой; способы управления допускаются только после проверки правил и технических ограничений.
- `browser_extension/` (будущий компонент) — браузерный UI, захват разрешённого визуального состояния, запуск/остановка агента и отображение диагностики.
- `slither_ai/advisor` — резервный режим рекомендаций человеку.
- `slither_ai/dashboard` — визуализация обучения и результатов.
- `configs`, `runs`, `checkpoints`, `results` — конфигурации и артефакты экспериментов.

## Этапы

1. Проверить и стабилизировать локальную среду.
2. Получить воспроизводимый PPO baseline и надёжную оценку.
3. Улучшить симуляцию, добавить противников и усложнить обучение.
4. Развить стратегию и проверить обобщение на новых сценариях.
5. Создать perception pipeline, способный распознавать состояние реальной игры.
6. Исследовать и реализовать браузерное расширение. Автономное управление включать только при подтверждённой допустимости; иначе предоставить Advisor mode.
7. Автоматизировать сравнение моделей и безопасное обновление best checkpoint.

## Быстрый старт

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e ".[dev]"
python -m slither_ai.cli smoke
```

Для обучения на NVIDIA GPU установите PyTorch отдельно по официальной инструкции под вашу версию CUDA, затем проверьте `torch.cuda.is_available()`. Наличие CUDA Toolkit само по себе не подтверждает доступность CUDA из PyTorch.

```bash
python -m slither_ai.cli train --timesteps 100000
python -m slither_ai.cli evaluate --episodes 20
```

## Принципы разработки

1. Сначала корректная локальная среда, затем обучение и перенос навыков.
2. Каждое улучшение подтверждается фиксированным evaluation-набором.
3. Лучший checkpoint не заменяется без измеримого улучшения.
4. Конфигурация, метрики, seed и версия кода сохраняются.
5. Онлайн-интеграция — отдельный этап с предварительной проверкой правил и разрешённых интерфейсов.
6. Не обходить антибот-защиту, не манипулировать приватным протоколом и не скрывать автоматизацию от механизмов защиты.
