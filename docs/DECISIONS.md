# Architecture Decision Log

## ADR-001 — Обучение в собственной локальной среде
**Статус:** Accepted

Обучать автономного агента в локальной симуляции, а не через автоматическое управление официальным Slither.io. Официальный клиент рассматривается как read-only источник визуальной информации для помощника человеку.

**Причины:** контролируемая физика, воспроизводимые seeds, безопасная нагрузка, быстрые массовые эпизоды и полный контроль над метриками.

## ADR-002 — Gymnasium API
**Статус:** Accepted

Среда должна реализовывать стандартный Gymnasium Env API. Это позволяет использовать готовые RL-библиотеки и стандартные инструменты проверки.

## ADR-003 — PPO как первый baseline
**Статус:** Accepted

Начать с PPO из Stable-Baselines3: устойчивый и широко используемый baseline для дискретного пространства действий. Сравнение с другими алгоритмами — после получения корректной среды и baseline.

## ADR-004 — Относительные дискретные действия
**Статус:** Accepted

Действия: left / straight / right относительно текущего курса. Это упрощает exploration и делает управление независимым от абсолютного угла.

## ADR-005 — Отделение train и evaluation
**Статус:** Accepted

Evaluation выполняется на фиксированных seeds, не участвующих в обучении. Кандидат становится best только после сравнения с текущей лучшей моделью.

## ADR-006 — Документы как обязательный handoff
**Статус:** Accepted

Каждая сессия обязана поддерживать ROADMAP, CHECKLIST, RESULTS, DECISIONS и NEW_CHAT_PROMPT. Новая сессия должна продолжать с конкретной задачи, не повторяя проектирование с нуля.
