## Роль и конечная цель проекта

Создать обучаемого автономного игрового агента для Slither.io:
- Сначала агент обучается в собственной воспроизводимой Slither.io-подобной среде.
- Затем мы развиваем perception, чтобы распознавать реальное игровое поле.
- Целевой сценарий применения: пользователь открывает официальную Slither.io, включает браузерное расширение Slither AI, а агент анализирует игру, выбирает действия и, если это допускают актуальные правила и разрешённые интерфейсы, передаёт игровые команды. Пользователь наблюдает за игрой и может остановить агента.
- До реализации автоматического ввода обязательно проверить актуальные правила и доступные способы интеграции. Не обходить антибот-защиту, CAPTCHA, rate limits, приватный протокол, скрытую инъекцию или anti-detection.
- Если автоматическое управление не разрешено, реализовать read-only perception + Advisor mode. Не подменять целевую задачу без явного объяснения.
- Локальная симуляция остаётся основным способом массового обучения; перенос на реальную игру требует отдельного perception/adapter layer и оценки sim-to-real gap.

## Следующая конкретная задача — runtime-валидация Phase 1

Выполни только проверку существующего MVP в целевом Linux-окружении пользователя. Код пока не запускался в целевой среде, поэтому нельзя переходить к PPO training или новым функциям, пока эта проверка не завершена.

Порядок:
1. Получить актуальный `main` и проверить, что рабочее дерево не содержит пользовательских изменений.
2. Установить проект: `pip install -e ".[dev]"`.
3. Запустить `pytest`.
4. Запустить `python -m slither_ai.cli smoke`.
5. Убедиться, что Gymnasium `check_env` проходит (он вызывается существующими тестами; если нет — проверить фактический тестовый код и не дублировать проверку без причины).
6. Особое внимание уделить девяти тест-кейсам: `NaN`, `+inf`, `-inf` для `arena_size`, `speed`, `turn_rate`.
7. Если тесты падают — исправить только подтверждённые проблемы, добавив/обновив соответствующие тесты. Не расширять scope.
8. Записать точные команды, версии зависимостей, результаты и ограничения в RESULTS.md; синхронизировать ROADMAP и CHECKLIST.

**Не запускай PPO training, не добавляй Pygame, opponents, vision или browser extension в этой сессии.** Это отдельные будущие задачи.

Если нет доступа к целевой машине, не имитируй запуск. Подготовь пользователю точные команды для выполнения и зафиксируй, что runtime-проверка остаётся pending.
