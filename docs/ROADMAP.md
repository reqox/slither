# Roadmap

Статусы: `TODO`, `IN_PROGRESS`, `BLOCKED`, `DONE`. Отмечать только фактически проверенные результаты. Конечная цель — обученный агент, применяемый в официальной Slither.io через браузерное расширение, если такое взаимодействие допускается правилами и доступными интерфейсами. Не обходить антибот-защиту и приватные механизмы игры.

## Phase 0 — Foundation
- [x] Зафиксировать миссию, границы и архитектурные принципы.
- [x] Создать документацию для передачи между сессиями.
- [ ] Проверить доступность GPU/PyTorch в целевом окружении.
- [ ] Зафиксировать воспроизводимую среду разработки и CI.

## Phase 1 — Local environment MVP
- [x] Реализовать первую Gymnasium-совместимую среду: reset/step/observation/reward/termination.
- [x] Добавить поддержку детерминированных seeds и базовые unit tests.
- [x] Отклонять NaN и бесконечные параметры физики в конструкторе среды.
- [x] Добавить CLI smoke test случайного агента.
- [ ] Запустить тесты и smoke test в целевом окружении; исправить выявленные проблемы.
- [ ] Добавить базовую отрисовку Pygame и режим headless.

## Phase 2 — PPO baseline
- [x] Добавить начальную CLI-команду обучения PPO с TensorBoard и сохранением модели.
- [x] Добавить начальную CLI-команду evaluation на последовательности фиксируемых seeds.
- [ ] Валидировать PPO train/evaluate end-to-end, сохранять per-episode JSON и конфиг эксперимента.
- [ ] Ввести best-checkpoint promotion только при статистически осмысленном улучшении.

## Phase 3 — Environment quality
- [ ] Улучшить геометрию и физику, сверить с выбранными игровыми правилами.
- [ ] Добавить управляемых scripted opponents.
- [ ] Добавить curriculum и domain randomization.
- [ ] Проверить перенос стратегии на ранее не встречавшиеся seeds.

## Phase 4 — Strategic agent
- [ ] Исследовать frame stacking / recurrent PPO.
- [ ] Добавить прогноз траекторий и опасностей.
- [ ] Добавить тактики охоты и оценки риска.
- [ ] Добавить tournament evaluation против разных классов оппонентов.

## Phase 5 — Perception / sim-to-real
- [ ] Определить визуальные объекты и координатную систему, необходимые агенту в реальной игре.
- [ ] Создать набор размеченных кадров/синтетических сцен и тесты качества распознавания.
- [ ] Реализовать read-only pipeline захвата и обработки доступного изображения.
- [ ] Сопоставить visual observations с observation contract агента или спроектировать отдельный adapter.
- [ ] Измерить latency и устойчивость распознавания при разных масштабах/сценах.

## Phase 6 — Browser extension / online integration
- [ ] Проверить актуальные правила Slither.io и доступные официальные/разрешённые интерфейсы интеграции; записать вывод и ограничения.
- [ ] Спроектировать browser extension: явные Start/Stop, статус, диагностика, безопасное отключение.
- [ ] Реализовать передачу визуального состояния из расширения в perception/inference pipeline.
- [ ] Автономную передачу игровых действий реализовывать только если она явно допускается правилами и доступными интерфейсами; не обходить anti-bot, не использовать приватный протокол, скрытую инъекцию или anti-detection.
- [ ] Если автономный ввод недопустим, реализовать Advisor mode с рекомендациями человеку.
- [ ] Провести контролируемые end-to-end тесты и задокументировать ограничения.

## Phase 7 — Research loop and model lifecycle
- [ ] Автоматизация серии экспериментов.
- [ ] Автоматическое сравнение кандидатов с baseline.
- [ ] Promotion/rollback по заранее заданным критериям.
- [ ] Отчёты о регрессиях и обобщающей способности.

## Definition of Done для каждой фазы
- Код и конфиги находятся в репозитории.
- Тесты и smoke/evaluation пройдены; результаты записаны в RESULTS.md.
- CHECKLIST и ROADMAP отражают фактическое состояние.
- DECISIONS содержит новые архитектурные решения и их причины.
- NEW_CHAT_PROMPT содержит ровно одну следующую небольшую задачу.
